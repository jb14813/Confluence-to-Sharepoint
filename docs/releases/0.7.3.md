# Confluence to SharePoint 0.7.3

Version 0.7.3 improves document/PDF import fidelity and recovery, adds JZB Apps branding, and supplies the current optional form companion. Imported pages remain editable native SharePoint drafts; users review and publish them in SharePoint.

## Downloads and updating

Use the [GitHub release](https://github.com/jb14813/Confluence-to-Sharepoint/releases/tag/v0.7.3) for these downloads and their SHA-256 files:

- `confluence-to-sharepoint-0.7.3.zip`: Chrome extension. Extract it and use **Load unpacked** in `chrome://extensions` for manual installation. Replace the existing unpacked directory and select **Reload** to update a manual installation.
- `confluence-to-sharepoint-0.7.3-source.zip`: complete corresponding source, including application changes, build recipes, lockfiles, notices and 229 upstream source/toolchain archives. This is not an installation package.
- `file-to-sharepoint-form.sppkg`: optional SharePoint form component, solution version **1.0.0.1**. An administrator installs or updates it on the selected site. Ordinary document imports do not require it.

The [Chrome Web Store](https://chromewebstore.google.com/detail/ahgjchhmbdpohnbeoccnpnfaeillcedm) remains the normal installation and automatic-update route. Google review and Store publication are separate from GitHub publication; check the Store's version. An unpacked installation has separate identity/storage and does not receive Store updates.

## Changes

- Preserve editable PDF reading order and supported link annotations, with native page-section links for internal destinations and explicit notes for unsupported actions.
- Convert combined evenOdd fill/stroke boxes through the established native paint operations. Preserve source-paint verification and the exact native image-dimension truncation limits.
- Reuse the bounded upload-throttling policy at the document-library root. Keep byte verification, uncertain-write protection and explicit recovery; uncertain uploads are not blindly repeated through another route.
- Recover one missing local image-staging acknowledgement using the same verified piece. Explicit refusals still stop.
- Check current-account access to form scripts served directly from the SharePoint catalog before setup and Send. Access loss, HTML redirects and temporary service errors produce an actionable refusal before form writes. No catalog or list permissions are changed by the extension.
- Build and verify the optional form package from current source. Keep incomplete-list-read rejection and nonce-preserving response recovery.
- Show JZB Apps as the primary workspace/source-page brand. Retain the original ONLYOFFICE logo as a compact linked legal credit.

## Verification scope

The current application passed **934 shared tests, 392 file-import tests and 16 form tests**, runtime dependency audits, native source/pin checks, real Chrome form controls and packaged-extension installation checks. A fresh public-source build reproduced all 202 runtime files exactly. The corresponding-source archive includes the complete verified preferred-source delivery. The converter amendment's second source preparation replayed cached compiler layers; it is not described as a second uncached full compile.

Live acceptance used **one tenant, nine site configurations and two identities**. The recorded corpus includes **350 Word imports** from 175 genuine exports on the 0.7.2 baseline and **213 PDF imports covering 175 distinct exports** across corrected validation candidates. These retain their original input and runtime hashes; they are not relabeled as imports of the final binary. Strong independent checks covered source text/word boundaries, stored native structure, lists, table merges, links, image order, uploaded bytes/dimensions and unpublished state.

Additional controls covered 36 format cases, 119 destination-policy cases, native edit/Save, desktop/mobile image rendering, cancellation and uncertain-write recovery. The final boxed readonly/multiline PDF was imported and edited on the real sites. Interactive form acceptance covered both the owner and external test account, required/readonly fields, choice/radio values, multiline responses, partial or denied reads, lost acknowledgements and duplicate prevention.

External respondents must be able to read the deployed form's static code assets as well as its definition and their own response records. Component discovery alone does not establish that access. The lab's asset grant was confined to the existing test account and this solution's code/license folder; unrelated catalog packages remained restricted. Administrators choose deployment and audience permissions for their own sites. The extension does not grant access.

## Supported behavior and limits

Chrome 127 or later and SharePoint Online are required. File import supports DOC, DOCX, ODT, RTF, UTF-8 text and text-based PDF, up to 50 MiB. Confluence capture also requires access to the source Confluence Cloud page. Original files stay local; reviewed reconstructed content and image assets are uploaded to the chosen site.

SharePoint reflow changes PDF geometry. Formatting is adapted to native alternatives and explained in conversion notes; this is not a positioned PDF editor. OCR/image-only PDFs, XFA, executable source scripts/macros, calculations, signatures, encrypted input and spreadsheet/slide imports are outside supported editable conversion. Mixed text/image PDFs require review for words still inside images. Unsubmitted form values remain in the current page only.

Site permissions and policies remain authoritative. A major-only page library cannot create an unpublished draft. Missing image-library access produces explicit picture-recovery notes/placeholders; it does not claim a successful image upload. These tests do not certify every document or unseen tenant.
