# Confluence to SharePoint 0.7.2

Published on GitHub on 2026-11-11. This guide describes that released build, not future source adapters or unreleased local work. The release tag remains `e4fe1d7348ec11559c16fed8717600ecfa1ecd25`; documentation corrections do not change its executable files or archives.

## Features

- Capture Confluence Cloud pages into new or existing SharePoint drafts. Track sent Confluence pages, refresh their source status and explicitly update selected imports. Updates replace the imported part, including edits made inside it in SharePoint; previous versions remain in SharePoint history.
- Import local DOCX, legacy DOC, ODT, RTF, UTF-8 TXT and text-based PDF files, up to **50 MiB**, using packaged conversion code inside Chrome. Open **Import a file** from the popup, dashboard or extension-added SharePoint shortcut, review the result and create a new draft. Files do not enter the Confluence source-update history.
- Preserve editable text, headings, lists, tables, vertical/horizontal merges, links and images. Formatting differences use native SharePoint alternatives with conversion notes. Headers/footers become labeled sections, notes become linked sections, content controls become ordinary content and fields retain static visible results.
- Import supported PDF text, multiline, checkbox, dropdown and radio fields as interactive controls using the optional administrator-installed form component. Ordinary document imports need no custom SharePoint component.

## Compatibility and limits

Desktop Chrome **127+**, Confluence Cloud on `atlassian.net` for page capture, and SharePoint Online on `sharepoint.com` are supported. Local files need no Confluence account. The destination needs a Site Pages library with versioning/minor drafts, view/add/edit permissions and image-upload access. Confluence Server/Data Center, SharePoint Server/on-premises, custom domains and major-version-only page libraries are outside this contract. Organization policies may restrict installation or access.

SharePoint reflows content; exact PDF page coordinates, fonts and decorative styles are not promised. Some graphics become verified images. **OCR is not included:** scans cannot become editable text, and mixed scanned/text PDFs need review. Direct XLSX/PPTX import is not included. Malformed/unreadable content, failed image verification, unsafe resources and complexity limits remain protected.

Interactive forms require administrator review, app-catalog deployment and installation on the selected site. Readers need definition access; respondents need permission to add and read their own response records. Permissions are not granted or elevated. XFA, signatures, scripts, calculations, multiselect/editable choices and some other advanced field behavior are unsupported; controls use page-grouped panels, not exact positioned overlays. [Installation and response-list requirements](../../products/file-to-sharepoint/sharepoint-form/README.md).

For the extension ZIP: extract it, open `chrome://extensions`, enable **Developer mode**, choose **Load unpacked** and select the folder containing `manifest.json`. This is a manual GitHub installation, not a Store installation. To update it, finish pending imports, replace the files in the same folder, select **Reload**, then refresh open source/destination pages. Unpacked and Store installations have separate identities/storage; do not assume history migrates between them or enable both copies for the same workflow. [Chrome's unpacked-install/reload instructions](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked).

The [Chrome Web Store listing](https://chromewebstore.google.com/detail/ahgjchhmbdpohnbeoccnpnfaeillcedm) remains the normal installation/update route. At the **2026-11-11 public-listing check it offered 0.6.2**. Version 0.7.2 was submitted for review separately; GitHub publication does not mean Google approval. Store installations receive the Store release when available; an unpacked copy does not receive Store updates.

## Verification scope

Recorded final-build checks: **1,288 passing tests**; **175 PDF documents / 387 pages** through conversion; **four real SharePoint draft imports** with persisted content/asset checks; and **two native-edit/Save checks**, including desktop/mobile images. The packaged bytes match the tested lab build and fresh public-source build. The 175-document corpus is conversion coverage, not 175 imports across multiple tenants.

Earlier shared-engine tests covered several SharePoint configurations, including approval, checkout and restricted accounts. The final file/PDF workflow was not rerun across that full matrix. Form acceptance established the lab owner's access, not every audience policy. These results do not certify every tenant, document or corporate configuration.

## Privacy, licensing and support

Conversion runs locally. The original file is not uploaded; reviewed reconstructed content, image assets and supported form definitions go to the selected SharePoint site. Linked-image fetching is explicit and omits cookies/referrer. Form answers remain in that site's lists under current-user permissions. There is no developer-operated conversion server, analytics or advertising. Confluence history, optional account history and Chrome sync are explained in the [privacy policy](https://jzbapps.com/apps/confluence-to-sharepoint/privacy/).
