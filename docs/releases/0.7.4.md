# Confluence to SharePoint 0.7.4

Version 0.7.4 brings file import into the familiar Confluence-style popout and makes the dashboard the single full-page history view. SharePoint remains the editor; all imports remain unpublished drafts.

## Downloads and updating

Use the [GitHub release](https://github.com/jb14813/Confluence-to-Sharepoint/releases/tag/v0.7.4) for these downloads and their SHA-256 files:

- `confluence-to-sharepoint-0.7.4.zip`: Chrome extension. Extract it and use **Load unpacked** in `chrome://extensions` for manual installation. Replace the existing unpacked directory and select **Reload** to update.
- `confluence-to-sharepoint-0.7.4-source.zip`: complete corresponding source, including application changes, build recipes, lockfiles, notices and 220 upstream source/toolchain archives. This is not an installation package.

The [Chrome Web Store](https://chromewebstore.google.com/detail/ahgjchhmbdpohnbeoccnpnfaeillcedm) remains the normal installation and automatic-update route. Store review and publication are separate from GitHub publication; check the listing's version. An unpacked copy has separate identity/storage and requires manual updates.

## Changes

- Open **Import a file** from SharePoint, the toolbar popup, dashboard or licenses page in one compact, reusable window. Keep the selected title and destination when reopening active work.
- Use the same remembered and pinned sites as the Confluence flow. Pages opened during conversion become available afterward; closing an unselected page removes that open-page choice.
- Create a new draft or choose an existing page and select **Add to bottom** or **Overwrite**, using the existing SharePoint sender. Review, edit and publish in SharePoint. No acceptance checkbox, local document editor or full-page import preview is required.
- Show actual Confluence last sent dates alongside the existing source checks and selected updates. Show file-imported destination pages and their last successful import date with **Import another file**.
- Retain only destination metadata for file history, up to 500 rows. Choose any supported file for a later import. Original uploads, local paths, filenames and source hashes are not retained as history, and local files are not watched or compared.
- Convert PDF field labels, current answers and selections to native editable page content. Preserve empty fields and masked passwords.
- Keep conditional conversion notes, linked-image consent, source/image verification and protection against repeating uncertain writes. Forgotten destination receipts stay forgotten when a completed capture is reopened.
- Keep JZB Apps branding and the compact linked ONLYOFFICE attribution.

Live interface acceptance used the authorized owner account on the existing main lab site. The nine existing site configurations were inspected without changing permissions. The engine binaries remain unchanged. Historical corpus receipts retain their original scope and runtime identities. These checks do not certify every document or unseen tenant.

## Supported behavior and limits

Chrome 127 or later and SharePoint Online are required. File import supports DOC, DOCX, ODT, RTF, UTF-8 text and text-based PDF, up to 50 MiB. Confluence capture also requires source-page access. Conversion runs inside Chrome; original source files are not uploaded.

Formatting uses the closest supported native SharePoint representation, with notes for actual adaptations or missing content. PDF geometry reflows. OCR/image-only PDFs, encrypted input, XFA, executable source scripts/macros, calculations, signatures and spreadsheet/slide imports are outside supported editable conversion. Mixed text/image PDFs need review for words still inside images. PDF field labels, current answers and checkbox/radio states become native editable text and table cells; empty values stay blank and passwords remain masked.

Site permissions and policies remain authoritative. Missing, denied, pending or unreachable pages do not automatically become a new-page import. A user can explicitly choose a new draft when an old destination is gone. Uncertain writes retain their attempt identity. SharePoint owns publishing and version history.
